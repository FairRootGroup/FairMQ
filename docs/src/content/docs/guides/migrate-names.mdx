The API of FairMQ is in the namespace `fair::mq`, and its headers are in the directory `fairmq/`. The old global names like `FairMQDevice` and the old headers like `<FairMQDevice.h>` still compile, but the compiler warns. This guide moves your code to the new names and lists each old name with its replacement.

## Before and after

```cpp title="mydevice.cxx (old)"
#include <FairMQDevice.h>

class MyDevice : public FairMQDevice
{
    bool HandleData(FairMQMessagePtr& msg, int);
};
```

```cpp title="mydevice.cxx (new)"
#include <fairmq/Device.h>

class MyDevice : public fair::mq::Device
{
    bool HandleData(fair::mq::MessagePtr& msg, int);
};
```

## Move your code

<Steps>

1. Replace the old `#include` lines. Use the table [Headers](#headers). [fairmq-tidy](/guides/fairmq-tidy/) can do this step for you.

2. Replace the old type names. Use the table [Type names](#type-names). [fairmq-tidy](/guides/fairmq-tidy/) can do this step for you.

3. If your `main()` comes from `runFairMQDevice.h`, move to `runDevice.h`. See [Replace runFairMQDevice.h](#replace-runfairmqdeviceh).

4. Replace the deprecated functions and members. Use the table [Functions and members](#functions-and-members).

5. Build with `-Werror=deprecated-declarations`. The compiler then stops at each remaining use of a deprecated name:

   ```sh
   cmake -S . -B build -DCMAKE_CXX_FLAGS="-Werror=deprecated-declarations"
   cmake --build build
   ```

</Steps>

## How the compiler warns

An old header contains a `#pragma GCC warning`. An old type name or member has the attribute `[[deprecated("…")]]`, and the compiler prints the text of the attribute. For the old code above, GCC and Clang print these warnings (the paths are shorter here):

<Tabs>
<TabItem label="GCC">

```txt
FairMQDevice.h:13:21: warning: Deprecated header: Use <fairmq/Device.h> instead
mydevice.cxx:5:47: warning: 'using FairMQMessagePtr = using fair::mq::MessagePtr = class std::unique_ptr<fair::mq::Message>' is deprecated: Use fair::mq::MessagePtr [-Wdeprecated-declarations]
```

</TabItem>
<TabItem label="Clang">

```txt
FairMQDevice.h:13:13: warning: Deprecated header: Use <fairmq/Device.h> instead [-W#pragma-messages]
mydevice.cxx:3:25: warning: 'FairMQDevice' is deprecated: Use fair::mq::Device [-Wdeprecated-declarations]
mydevice.cxx:5:21: warning: 'FairMQMessagePtr' is deprecated: Use fair::mq::MessagePtr [-Wdeprecated-declarations]
```

</TabItem>
</Tabs>

The compiler does not show all uses:

- GCC 13 does not warn for a deprecated alias in a list of base classes, for example `class MyDevice : public FairMQDevice`. Clang and fairmq-tidy find it.
- [`<fairmq/FwdDecls.h>`](/source/fairmq/FwdDecls.h/#L29-L43) declares twelve of the old names again, without the attribute. A file that includes only this header gets no warning for these names.
- An old header warns only if the file did not include the new header before. `FairMQLogger.h` always warns. `runFairMQDevice.h` does not warn.
- `FairMQDevicePtr` of `runFairMQDevice.h` has no attribute.

Each old header includes the new header, so the old `#include` lines still work. The include directories of an installed `FairMQ::FairMQ` are `include` and `include/fairmq`, so the old headers also work with the prefix `fairmq/`, for example `<fairmq/FairMQDevice.h>`.

## Replace runFairMQDevice.h

[`runFairMQDevice.h`](/source/fairmq/runFairMQDevice.h/) and [`runDevice.h`](/source/fairmq/runDevice.h/) both contain a `main()` function. Your code gives the two functions `getDevice()` and `addCustomOptions()`. The signature of `getDevice()` is different:

| Header | Declaration of `getDevice()` |
| --- | --- |
| `runFairMQDevice.h` | `FairMQDevicePtr getDevice(const fair::mq::ProgOptions& config);` with `FairMQDevicePtr` = `fair::mq::Device*` |
| `runDevice.h` | `std::unique_ptr<fair::mq::Device> getDevice(fair::mq::ProgOptions& config);` |

`addCustomOptions(boost::program_options::options_description&)` is the same in both headers.

```cpp title="Old code"
#include <runFairMQDevice.h>

FairMQDevicePtr getDevice(const fair::mq::ProgOptions& /*config*/)
{
    return new MyDevice();
}
```

The new code returns a `std::unique_ptr`, and the parameter is not `const`. The example 1-1 uses the new header:

## CMake names

The CMake package is `FairMQ`. Link your targets with `FairMQ::FairMQ`. The executables of FairMQ are imported targets with the same prefix, for example `FairMQ::fairmq-bsampler`. See [Use FairMQ in a CMake project](/start/cmake/).

## Automate the move with fairmq-tidy

`fairmq-tidy` finds the old headers, most old type names, the deprecated functions and members, and a `getDevice()` for `runFairMQDevice.h`. With `--fix`, it replaces most of them in your files. See [Check code with fairmq-tidy](/guides/fairmq-tidy/) and the [list of checks](/tools/fairmq-tidy/#checks).
